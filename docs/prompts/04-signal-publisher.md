# Промт 04 — Калибровка и публикация сигналов в бота

---

Ты — инженер ML-продакшена. Репозиторий `market-regime-dashboard`, ветка `claude/modest-tesla-bcavni`, мой Mac.
Готово: слой данных (промт 02), модель и валидация (промт 03), бот на VPS (промт 01) с HTTP API.
Прочитай `bot/README.md` (раздел «Как модель присылает сигналы»), `bot/client/push_signal.py`,
`bot/regime_bot/signals.py` (валидация полей), `prediction_log.py` и раздел 4 отчёта
`docs/research/regime-ai-stack-2026-09.md`.

**Цель:** на Mac работает сервис, который превращает прогнозы модели в сигналы, отправляет их в бот,
сам закрывает их по цене и копит честную статистику.

## Что сделать
1. `calibration.py` — конформные интервалы и калибровка вероятностей: MAPIE 1.5 (`TimeSeriesRegressor`, EnbPI/ACI,
   метод `.update()` по мере закрытия исходов) и/или crepes; Brier и reliability считать в `prediction_log.compute_stats()`.
   Ежемесячная проверка покрытия интервалов; при падении покрытия — расширять интервалы или воздерживаться (abstain).
2. `signal_publisher.py`:
   - берёт прогноз, у которого откалиброванная вероятность ≥ порога и есть уровень отмены сценария;
   - строит сигнал в формате бота: `ext_id` (детерминированный: актив-таймфрейм-время бара), `asset`, `timeframe`,
     `side`, `entry`, `stop` (= уровень отмены), `targets` (1–3), `confidence` (калиброванная), `regime`, `horizon`,
     короткий `rationale` (≤ 700 символов, без слов «гарантия», «точный прогноз», «доходность X%»);
   - **outbox в SQLite**: запись → отправка через `push_signal()` → отметка; при сетевой ошибке — повтор с backoff
     (повторы безопасны: бот дедуплицирует по `ext_id`);
   - записывает сигнал в `prediction_log.py`.
3. `signal_monitor.py` — каждую минуту проверяет открытые сигналы по свечам (high/low) и закрывает их через
   `close_signal(ext_id, "tp"|"sl"|"closed", result_pct)`: по первой коснувшейся цели/стопу; по истечении горизонта —
   `closed` по цене закрытия; если вход так и не был достигнут — `cancelled`. `result_pct` — от входа до выхода,
   без плеча; при нескольких целях — правило частичного закрытия опиши в README и применяй последовательно.
4. Лимиты на спам: не больше N сигналов в день, не больше одного открытого сигнала на актив-таймфрейм.
5. Режим **беты**: переменная `REGIME_API_URL` может указывать на тестовый экземпляр бота/чат; первые недели сигналы
   идут только в закрытую бета-группу, статистика копится (цель — сотни закрытых событий на горизонт).
6. Запуск под тем же `launchd`-движком из промта 02 (джобы APScheduler), алерт в Healthchecks, если сигналы не
   отправляются или outbox растёт.
7. Тесты: формирование сигнала проходит валидацию бота (импортируй `validate_signal` из `bot/regime_bot/signals.py`);
   монитор правильно закрывает LONG/SHORT по свечам; outbox переживает падение сети.

## Ограничения
- Секрет `REGIME_API_SECRET` — только в `.env` на Mac, никогда в коде/логах/коммитах.
- Mac только **исходящие** HTTPS-запросы, никаких открытых входящих портов.
- Публикация платным подписчикам включается флагом `PUBLISH_LIVE=1` только после прохождения гейта из промта 03.

## Готово, когда
- В бета-режиме сигналы приходят в Telegram, итоги закрываются автоматически, `/stats` в боте совпадает с
  `prediction_log`; тесты зелёные; README с запуском/остановкой; всё запушено.
