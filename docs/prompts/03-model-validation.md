**Ключевая мысль отчёта:** HMM-режимы, волны Эллиотта и оценка Claude — это **признаки**, а не прогнозист.
Прогнозист — градиентный бустинг на мета-метках, и его качество надо доказать, а не предположить.

**Цель:** модель, которая выдаёт калибруемую вероятность «основной сценарий сработает до барьера», и отчёт,
который честно отвечает: бьём ли мы случайное блуждание после комиссий.

## Что сделать
1. `labels.py` — triple-barrier метки (барьеры ±k·σ по GARCH, вертикальный барьер = горизонт), события —
   смена режима / новый топ-кандидат волны; мета-метка «primary-направление сбылось»; веса по уникальности.
2. Режимы: использовать только **filtered (каузальные)** вероятности HMM (forward-алгоритм, не smoothed);
   добавить `regime_msar.py` (statsmodels MarkovAutoregression, filtered) и `changepoint.py` (Bayesian online
   change-point, ~80 строк своей реализации). Все три — признаки.
3. `ml_forecaster.py` — LightGBM 4.7 и CatBoost 1.2 на признаках из промта 02 + режимы + волны; фиксированные
   гиперпараметры, выбранные внутри purged-CV (optuna — только внутри, все trial'ы логировать).
4. `validate.py` — CombinatorialPurgedCV (пакет `purgedcv` или `skfolio`), purge ≥ вертикального барьера,
   embargo ~2%; метрики: Brier, log-loss, reliability/ECE; для стратегии на сигналах — expectancy после комиссий
   (0.05% фьючерсы / 0.10% спот + проскальзывание), Sharpe с издержками, PSR, **Deflated Sharpe с честным N**
   (все запуски и trial'ы), **PBO** по путям CPCV, minimum track-record length. Бэктест — vectorbt (MIT).
5. **Бейзлайны, которые обязаны быть побиты:** случайное блуждание / бутстрап (`monte_carlo.py`), простые правила,
   Chronos-2 zero-shot (Apache-2.0; только на периоде после его даты обучения). НЕ использовать TimesFM 3.0 и
   Moirai 2.0 (non-commercial), backtesting.py и pypbo (AGPL), mlfinlab (проприетарный) в продаваемом продукте.
6. MLflow 3 (sqlite backend) — эксперименты, артефакты, модель-реестр; каждый запуск увеличивает N для DSR.
7. `reports/validation_<дата>.md` — сводный честный отчёт: таблица метрик по активам/таймфреймам/режимам,
   reliability-график, сравнение с бейзлайнами, вердикт гейта.

## Гейт (не обсуждается)
Модель допускается к публикации сигналов, только если **DSR > 0.95, PBO < 0.2, expectancy после издержек > 0 на всех
тестовых путях**. Если не проходит — так и напиши в отчёте и предложи, что улучшать; не подгоняй параметры под тест.

## Ограничения
- Никакого KFold/TimeSeriesSplit без purge/embargo. Никаких smoothed-вероятностей и in-sample отбора признаков.
- Не трогай Streamlit-страницы, кроме добавления новой страницы с отчётом валидации (по желанию).
- Покрой тестами `labels.py` и `validate.py` (в т.ч. тест на утечку: перемешанные будущие данные не меняют прошлые метки).
