# Промт 00 — Собрать и запустить всё на своём компьютере (Windows / macOS / Linux)

Главный промт: вставьте его целиком в Claude Code (десктоп или терминал) на любом компьютере.
Он соберёт ролики, проверит бота, прогонит лабораторию сигналов на реальных данных и дальше поведёт
по остальным промтам этой папки.

---

Ты — ведущий инженер проекта REGIME AI. Работай на моём компьютере, в моём терминале. Объясняй по-русски,
коротко и по делу; перед каждым шагом, который что-то устанавливает, говори, что именно и зачем.

## Контекст проекта
Репозиторий `https://github.com/bitglumerzz/market-regime-dashboard`, рабочая ветка `claude/modest-tesla-bcavni`
(открыт PR #1 в `master`). Что в нём уже есть:

## Шаг 1. Проверь систему и поставь недостающее
Определи ОС и архитектуру. Нужны: **git**, **Python 3.9+**, **Node.js 18+ (LTS)**. ffmpeg ставить не обязательно —
`build_all.py` возьмёт его из pip, если его нет в PATH.
- macOS: Homebrew → `brew install git python node` (если чего-то нет).
- Windows: `winget install Git.Git Python.Python.3.12 OpenJS.NodeJS.LTS`, затем открыть **новый** терминал.
  Работаем в PowerShell; WSL не нужен.
- Linux: пакетный менеджер дистрибутива (для Node — nodesource или nvm, если версия < 18).
Покажи версии (`git --version`, `python --version` / `python3 --version`, `node --version`) и только потом иди дальше.

## Шаг 2. Получи код
```
git clone https://github.com/bitglumerzz/market-regime-dashboard
cd market-regime-dashboard
git checkout claude/modest-tesla-bcavni
```
(Если PR #1 уже слит — работай из `master`.) Если репозиторий приватный и клонирование просит логин — помоги
авторизоваться через `gh auth login` или HTTPS-токен, не показывая токен в чате.

## Шаг 3. Проверочный прогон (2–3 минуты)
`python build_all.py --fast` (на macOS/Linux может быть `python3`). Он создаст `.venv`, поставит зависимости Python,
`npm install` и Chromium для Playwright, отрендерит по 3 проверочных кадра промо и интро (`still_*.png`) и прогонит
тесты бота. Открой 2–3 кадра и покажи мне, что рендер корректный (шрифты кириллицы, золото на тёмном фоне).
Если что-то упало — найди причину в выводе и почини (частые: старый Node, нет прав на установку Chromium,
корпоративный прокси — тогда `HTTPS_PROXY`), не меняя анимацию и звук.

## Шаг 4. Персонализация (спроси меня)

  Если у меня другие — передай через параметры рендера: `node studio/promo/render.js --brandA … --brandB … --model "…" --bot @…`

## Шаг 5. Полная сборка роликов (10–30 минут)
`python build_all.py` (все три стиля звука) или `python build_all.py --styles deep`. В конце выведи список файлов с размерами:
`studio/promo/promo_sound*.mp4`, `studio/promo/ad_18s*.mp4`, `studio/intro/intro.mp4`. Открой рекламную нарезку.
Файлы MP4 не коммить (они в `.gitignore`).

## Шаг 6. Лаборатория сигналов на реальных данных — главный вопрос проекта
Цель: выяснить, какие признаки **реально** предсказывают направление BTC и ETH на горизонтах от 4 часов до нескольких дней.
1. `.venv` + `pip install -r signal_lab/requirements.txt`.
2. Скачай данные (публичные эндпоинты Binance, без ключей):
   `python -m signal_lab.fetch --symbol BTCUSDT --tf 4h`, то же для `ETHUSDT`, и `--tf 1d` для обоих.
   Если Binance недоступен из моей сети — скажи об этом и предложи варианты (bulk-архивы data.binance.vision,
   VPS вне РФ из промта 01, другая биржа через ccxt); ничего не обходи без моего согласия.
3. Прогоны: 4h с горизонтами 6 и 18 баров (1 и 3 дня), 1d с горизонтами 1 и 3; комиссия 10 б.п. за сторону:
   `python -m signal_lab.run --data data/BTCUSDT_4h.parquet --tf 4h --horizon 6` и т. д.
4. Сведи результаты в `reports/signal_lab_summary.md`: какие признаки значимы после поправки (q < 0.05) и стабильно
   для обоих активов, какова лучшая модель, прошёл ли гейт (DSR > 0.95, средняя сделка после комиссий > 0, ≥ 100 сделок).
   **Правило честности:** не подбирай параметры под результат; если что-то меняешь — это новая попытка, и она
   увеличивает счётчик испытаний для DSR (перечисли все попытки в отчёте).
5. Если в `docs/research/directional-edge-2026-09.md` есть список гипотез H1…Hn — проверь их по порядку приоритета
   (промт `07-edge-experiments.md`), добавляя признаки в `signal_lab/features.py` с тестом на отсутствие заглядывания вперёд.

## Шаг 7. Дальше — по плану
Покажи мне таблицу из `docs/prompts/README.md` и предложи следующий шаг. Обычный порядок:
**01** бот на VPS → **02** движок данных на Mac (архиватор фандинга/OI — чем раньше, тем лучше: история живёт 30 дней) →

## Правила на всю работу
- Секреты (токен бота, `SIGNAL_API_SECRET`, ключи API) — только в `.env`, никогда в чат, код, логи и коммиты.
- Коммить в рабочую ветку небольшими осмысленными коммитами; перед пушем — тесты (`bot/`, `signal_lab/`).
- Никаких формулировок «гарантированная доходность», «точный прогноз», «доходность X%» — ни в коде, ни в текстах.
- Платный запуск сигналов — только после прохождения гейта качества и разговора с юристом.
