# H-ApexCloud — индикатор Apex Cloud (TradingView, veilazaro010)

**Статус: спецификация зафиксирована, результаты не считались.** Правило ниже записано по структуре данных
(названия колонок, частота событий, их кардинальность) — без единого взгляда на доходность. Коммит с этим файлом
предшествует запуску `signal_lab/apex_cloud.py`.

## Источник данных
Пользователь выгрузил историю графика из TradingView («Экспорт данных графика», таймфрейм 240 = 4H) для трёх
инструментов. Вместо XRP выгружен DOGE — отмечаю это явно, не подменяю тихо.

| файл | биржа | инструмент | баров | период |
|---|---|---|---|---|
| `BINANCE_SOLUSDT.P, 240.csv` | Binance perp | SOLUSDT | 13250 | 2020-09-14 — 2026-10-01 (≈6.05 года) |
| `BYBIT_BNBUSDT.P, 240.csv` | Bybit perp | BNBUSDT | 2526 | 2025-08-06 — 2026-10-01 (≈1.15 года) |
| `BYBIT_DOGEUSDT.P, 240.csv` | Bybit perp | DOGEUSDT | 2526 | 2025-08-06 — 2026-10-01 (≈1.15 года) |

На графике одновременно два индикатора. К Apex Cloud относятся только: `Cloud top/bottom`, `Mid`, `Zone +/−`,
`SSL high/low`, `Cloud flip ▲/▼`, `SSL flip ▲/▼`, `Trend UP/DOWN`, `Divergence BUY/SELL`. Колонки `RSX`, `RSI`,
`RSI-based MA`, `Shapes*`, `Regular Bullish/Bearish` — отдельный индикатор RSI-дивергенций, не используются.

## Механика (по структуре, не по доходности)
- `Trend UP` / `Trend DOWN` — бинарные флаги, max_run=1 (одиночные события), никогда не равны 1 одновременно.
  Число событий на SOL (26/25 за 6 лет) близко к `SSL flip` (26/25) и меньше `Cloud flip` (39/40) — согласуется
  с описанием автора: «TREND появляется, когда облако и канал подтверждения совпали». Это **первичный сигнал**.
- `Cloud flip ▲/▼` — тот же тип событий, без подтверждения каналом; чаще. Второй (более шумный) вариант правила.
- `Divergence BUY/SELL` — реже всех (18/13 на SOL); по описанию — предупреждение об ослаблении, не точка входа.
- Время в CSV — ISO8601 со смещением +03:00 (локальная зона пользователя в TradingView); конвертируется в UTC.
- Цена берётся из самого CSV (`open/high/low/close`), а не из отдельной загрузки Binance/Bybit — ряд должен
  совпадать с тем, на основе которого индикатор вычислял облако.

## Правило (зафиксировано)
**Stop-and-reverse**, без барьеров (у индикатора нет цели/стопа — он показывает только направление тренда):
- Позиция 0 до первого сигнала. `Trend UP` → long, `Trend DOWN` → short. Вход по открытию **следующего** бара после
  бара сигнала (публикационная задержка). Позиция удерживается до противоположного сигнала (переворот) или до
  конца ряда.
- **Основной вариант A** (предсказанный «первичный» сигнал): входы по `Trend UP/DOWN`.
- **Контрольный вариант B** (более шумный): входы по `Cloud flip ▲/▼`, без подтверждения каналом.
- Издержки: SOL (Binance USDⓈ-M) — 5 б.п. за сторону; BNB/DOGE (Bybit USDT perp, taker 0.055 %) — 5.5 б.п. за сторону.
  Переворот = 2 стороны, первый вход после 0 = 1 сторона.
- Сравнение: buy & hold на том же окне; плацебо — число и чередование знаков событий сохраняются, но их позиции
  на оси времени переставлены случайно (тест на то, несёт ли информацию именно *момент* сигнала Apex Cloud,
  а не просто частота разворотов).

## Ограничения, обозначенные заранее
- **SOL**: 25–26 сделок за 6 лет — ниже порога 100 сделок из общего гейта; ДИ будут широкими. Любой результат —
  ориентир, не прошедший гейт по построению (мало сделок), если явно не укажу обратное.
- **BNB/DOGE**: 5–6 сделок за 14 месяцев — статистической мощности нет. Ожидаемый вердикт — «нет ответа», как в H6.
- Биржа индикатора (Bybit для BNB/DOGE) не совпадает с биржей, на которой считался весь прошлый анализ (Binance).
  Это сознательный выбор: тестируем индикатор на тех же данных, на которых он сам считал облако.
- Данные выгружены один раз вручную — это не повторяемый пайплайн; при желании повторной проверки нужна новая
  выгрузка (или forward-тест через TradingView-алерты, см. ниже).
- Параметры индикатора — значения по умолчанию (облако на 1D, остальное не менялось пользователем при выгрузке).
  Подбор параметров не делается.
